# EFX

**EFX إطار عمل مستقل لتطوير قواعد البيانات في .NET، بطموح أن يصبح بديلاً أكثر قوة من Entity Framework Core.**

يعتمد EFX على منهجية Model-First: يكتب المطور نماذج C# المعتادة، ثم يفحص EFX قاعدة البيانات ويقارن بنيتها بالنماذج ويجهّز خطة تغييرات واضحة.

## الجديد: Zero-Command Schema Sync

يمكن للتطبيق طلب مزامنة المخطط ضمن دورة التشغيل العادية، دون الحاجة إلى أمر ترحيل منفصل. لكن هذا لا يعني إجراء تغييرات صامتة على قاعدة البيانات؛ إذ يجب على التطبيق توفير موافقة صريحة قبل التطبيق. دون الموافقة لن ينفذ EFX أي تغيير.

```csharp
var engine = new EfxEngine();
var provider = new SqliteProvider();

var result = engine.Sync(
    typeof(Program).Assembly,
    provider,
    "Data Source=app.db",
    plan =>
    {
        Console.WriteLine(plan.ToDisplayString());
        Console.Write("اكتب APPLY للموافقة: ");
        return Console.ReadLine()?.Trim() == "APPLY";
    });
```

راجع [دليل Zero-Command Schema Sync](docs/zero-command-schema-sync.md) لمعرفة آلية الموافقة والحماية والقيود الحالية.

## الإمكانات المنفذة حاليًا

- اكتشاف فئات النماذج داخل مساحات الأسماء التي تحتوي على `Models`.
- اكتشاف الخصائص scalar فقط واستبعاد خصائص التنقل والكائنات والعلاقات.
- اعتماد `Id` أو `{ModelName}Id` كمفتاح أساسي تقليدي، مع دعم أساسي للسمات `[Key]` و`[Table]` و`[Column]` و`[Required]` و`[NotMapped]`.
- استخدام أسماء الجداول بالجمع افتراضيًا، مع اكتشاف أسماء الجداول المفردة التي استخدمها النموذج الأولي السابق حتى لا ينشئ جدولًا مكررًا بجانب بياناتك القديمة.
- فحص جداول وأعمدة SQLite.
- مقارنة وجود الجداول والأعمدة، والتوافق النوعي في SQLite، وقابلية NULL، وحالة المفتاح الأساسي.
- إنشاء خطة تغييرات ومعاينة SQL واضحة.
- إنشاء الجداول الناقصة وإضافة الأعمدة الاختيارية غير المفتاحية بعد موافقة صريحة.
- منع التغييرات الخطرة أو غير الواضحة والخرائط المكررة أو غير المدعومة وتحويلها إلى مراجعة يدوية.
- إعادة التحقق من المخطط بالكامل قبل التنفيذ وداخل المعاملة لاكتشاف أي تغيير متزامن؛ وعدم إنشاء ملف قاعدة البيانات عند التخطيط فقط؛ وإنشاء نسخة احتياطية مؤرخة قبل تعديل قاعدة SQLite موجودة على ملف، وتنفيذ DDL داخل معاملة.
- رفض قواعد الذاكرة وروابط SQLite من نوع URI حاليًا إلى أن تتوفر آلية نسخ احتياطي يمكن التحقق منها.

## تشغيل المشروع وتجربته

يتطلب المشروع .NET 11 SDK.

```bash
dotnet restore EFX.sln
dotnet build EFX.sln --configuration Release
dotnet test EFX.sln --configuration Release
dotnet run --project samples/EFX.Sample -- efx-demo.db
```

ويمكن تشغيل العينة من خلال CLI أيضًا:

```bash
dotnet run --project src/EFX.Cli -- demo efx-demo.db
```

ستظهر النماذج وSQL المقترح. لن تتغير قاعدة البيانات إلا بعد كتابة `APPLY` بشكل صريح. عند تشغيل المثال مرة أخرى ستظهر رسالة تفيد بأن المخطط متزامن ولا توجد تغييرات.

## هيكل المشروع

- `src/EFX.Core` - اكتشاف النماذج والبيانات الوصفية وخطط المخطط وآلية المزامنة بموافقة صريحة.
- `src/EFX.Sqlite` - فحص SQLite وتوليد SQL والنسخ الاحتياطي والتنفيذ داخل معاملة.
- `src/EFX.Cli` - واجهة سطر أوامر قابلة للتشغيل لعرض العينة.
- `samples/EFX.Sample` - نماذج وعينة Zero-Command Schema Sync.
- `tests/EFX.Tests` - اختبارات الوحدة والتكامل مع SQLite.
- `docs` - المعمارية والحماية وخطة التطوير.

## حدود الحماية في هذه النسخة

لا يطبق EFX أي تغيير دون موافقة صريحة. كما لا يحذف جداول أو أعمدة تلقائيًا، ولا يفترض أن تغيير الاسم يعني الحذف والإنشاء، ولا يحوّل البيانات الموجودة، ولا يغيّر المفتاح الأساسي أو النوع أو قابلية NULL تلقائيًا، ولا يضيف عمودًا إلزاميًا إلى جدول قائم دون استراتيجية تعبئة افتراضية تمت مراجعتها. أي حالة من هذه الحالات توقف الخطة بالكامل بدل تطبيق جزء منها فقط.

يدعم مزود SQLite حاليًا مجموعة محدودة عمدًا: إنشاء الجداول الناقصة وإضافة الأعمدة الاختيارية غير المفتاحية. المشروع ما زال في مرحلة مبكرة، وهذه الإجراءات لا تعني ضمان انعدام المخاطر. اختبر دائمًا على نسخة قابلة للاستعادة قبل استخدام الإنتاج.

## حالة المشروع

هذه نسخة تأسيسية لاكتشاف النماذج ومقارنة المخطط ومزامنة SQLite الآمنة بعد المراجعة. ما زالت الفهارس والعلاقات والمفاتيح المركبة وإدارة إصدارات المخطط والاستعلامات ومزودات قواعد البيانات الأخرى ضمن التطوير المستقبلي.
